# 电商客服 Agentic AI 系统

一个基于 **LangGraph** 的电商智能客服系统：用户一句话进来，由意图路由分发到**订单查询**、**售后决策**、**闲聊兜底**三条链路，最终通过 **MCP** 打通真实支付，形成「问答 → 决策 → 执行」的闭环。

不是只会聊天的机器人，拥有
它会真的查库、真的判规则、真的退款。

精确跨表查询，有自省环节；指代词消解，有记忆机制；售后判断冲突，引入大模型审核-不足时走人工；售后事实判断，有追问反问环节，让对话畅通无阻。
---

## 它能做什么

| 场景 | 用户说的话 | 系统做什么 |
|---|---|---|
| 订单查询 | "我的订单到哪了" | Text2SQL 动态生成查询，跨表 JOIN 出物流轨迹 |
| 售后决策 | "订单3要退款，尺码不合适" | 查签收时效、品类、运费险 → 规则判定 → 灰区交给 LLM → 真退款 |
| 政策咨询 | "定制商品能退吗" | 两跳 RAG 检索政策条款，直接引用条款回答 |
| 多轮追问 | "那它到哪了" / "我们刚才聊的哪个订单" | Checkpointer + 四层记忆，消解省略与指代 |
| 闲聊 | "你好" | 带用户画像的自然对话 |

## 核心设计

### 1. 三条链路，职责不重叠

```
              ┌─ intent ─ manager ─┬─ order_query   Text2SQL，负责"展示"
用户输入 ─────┤                    ├─ after_sales   规则+LLM，负责"决策并动钱"
              └────────────────────┴─ chat          记忆+闲聊，负责"兜底"
```

**为什么售后不复用订单查询子图？**
订单查询解决"不知道用户要查什么"，需要 Text2SQL 的灵活性；
售后要的是固定字段集合（签收天数、实付金额、品类、运费险、既有售后单），
用参数化查询 **0 次 LLM 调用**、结果精确、可审计。
拿一条不确定的 SQL 去驱动退款是事故。

### 2. 售后决策：规则引擎 + LLM 混合

- **程序判**：时效（7 天无理由 / 15 天换货 / 1 年保修）、金额（按实付算）、品类、是否已有售后单
- **LLM 判**：责任归属、替代方案、政策灰区

规则 fail 时**不直接拒绝用户**，而是标记 `conflict_detected` 交给 LLM 复核 —— 例如"已超 7 天但符合 15 天换货"，系统会自动把退货降级为换货，而不是冷冰冰地说"不能办"。

> **金额永远不由 LLM 决定。** 规则层算钱，执行层只管调用。

### 3. Text2SQL 三层防线

```
Schema 裁剪  →  正则安全校验（禁写 / 强制 user_id）  →  只读执行
```
失败时把数据库报错拼回提示词**自省重试**，最多 3 次。

### 4. 政策 RAG：两跳检索

向量 + BM25 + RRF 融合召回条款；第一跳覆盖不足时，由 LLM 判断并给出补充检索词再检一次。
政策文档按 `## POLICY-01 退货政策` 切分，**编号写在文档里**而不是按顺序推导 —— 否则调整章节顺序会让所有依据引用错位。

### 5. MCP 打通执行层

| 能力 | 状态 |
|---|---|
| 支付宝退款 / 收款 / 查单 | **真实**，连阿里云百炼 MCP 广场（SSE） |
| 物流查询 | 桩，返回固定两行 |
| 售后工单 | 桩，返回固定两行 |

支付调用集中在 `after_sales_node` 一处（异步），子图里的执行节点只标记 `pending`。

### 6. 流式输出只做一次

`graph.astream(stream_mode="messages")` 在传输层统一流式，节点只负责返回一条消息。
**节点里不要套 `create_agent` 再 astream** —— 子图的模型调用会落在嵌套命名空间里，
外层收不到 token（实测：直接调模型 14 个 token 事件，套一层只剩 1 个完整消息）。

## 快速开始

```bash
# 1. 克隆
git clone https://github.com/ff03062/order_customer_service.git
cd order_customer_service

# 2. 一键装依赖（Windows 双击即可）
install.bat

# 3. 配置环境变量
copy .env.example .env
#   然后按 docs/环境变量说明.md 填写

# 4. 启动
run.bat
```

启动后自动打开 `http://127.0.0.1:8001/login`。

> 只需要跑通"订单查询 + 政策咨询"，最少要准备：**MySQL + PostgreSQL + Redis** 和一个 DashScope API Key。

环境变量、数据库建表、外部服务准备 => [docs/环境变量说明.md](docs/环境变量说明.md)
系统结构、子图拓扑、设计取舍 => [docs/项目参考文档.md](docs/项目参考文档.md)

## 已知限制

- **Schema 图谱未接入**：`schema_select_node` 用意图→表 的硬编码映射，表结构变化需要改代码。但经过思考，其实这块用scheam硬裁剪是个不错的选择了（即写死）
- **物流 / 工单是桩**：返回固定字符串，接口形态与真实 MCP 一致，替换只改一个文件。
- **意图识别是单轮分类**：跨话题切换、复杂指代仍有误判。
- **没有二次确认**：目前规则判定通过即执行退款，生产环境必须加用户确认环节。
